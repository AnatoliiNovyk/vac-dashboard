# Changelog: Впровадження системи автентифікації за ІПН

## Дата
28.05.2024

## Опис змін

Проведено повний рефакторинг системи автентифікації. Замість входу за допомогою попередньо створених email/пароль, реалізовано безпечний механізм входу за ідентифікаційним номером платника податків (ІПН) співробітника.

Це усуває необхідність вручну створювати користувачів в Firebase Auth та дозволяє будь-якому співробітнику, зареєстрованому в базі даних Firestore, отримати доступ до системи.

## Технічна реалізація

### 1. Бекенд: Створення Cloud Function

- **Створено нову Cloud Function `signInWithTaxId`** (`functions/index.js`).
- **Призначення функції:**
    1. Прийняти ІПН (`tax_id`) від клієнтського додатку.
    2. Здійснити пошук співробітника з таким ІПН в колекції `employees` у Firestore.
    3. У разі успішного пошуку, згенерувати **кастомний токен автентифікації** (Custom Auth Token) для знайденого користувача, використовуючи його `uid`.
    4. Повернути цей токен клієнту.
- **Безпека:** Функція виступає як безпечний серверний посередник, який перевіряє ІПН та видає короткотривалий дозвіл на вхід. Паролі повністю виключені з процесу.

### 2. Фронтенд: Оновлення інтерфейсу та логіки

- **Оновлено `index.html`:**
    - Екран "Очікування автентифікації" замінено на повноцінну **форму входу**, що містить поле для вводу ІПН та кнопку "Увійти".
- **Оновлено `app.js`:**
    - Додано логіку для обробки відправки форми входу.
    - При відправці форми, клієнт викликає хмарну функцію `signInWithTaxId`.
    - Після отримання кастомного токена від функції, клієнт використовує метод `auth.signInWithCustomToken(token)` для безпечного входу в систему Firebase.
    - Після успішного входу спрацьовує стандартний слухач `onAuthStateChanged`, який ініціалізує робочу панель.

### 3. Конфігурація

- **Оновлено `firebase.json`:**
    - Додано секцію `"functions"`, щоб вказати Firebase наявність та розташування хмарних функцій.
    - Виправлено конфігурацію хостингу (`hosting.public`), щоб вона вказувала на кореневу директорію (`.`), що усунуло помилку `Cannot GET /`.

## Вплив на систему

- **Підвищена безпека:** Автентифікація тепер контролюється на стороні сервера, а паролі повністю виключені з процесу.
- **Покращений досвід користувача:** Співробітникам для входу потрібен лише їхній ІПН.
- **Масштабованість:** Для надання доступу новому співробітнику достатньо просто додати його до бази даних Firestore. Немає потреби створювати для нього окремий обліковий запис в Firebase Authentication.
