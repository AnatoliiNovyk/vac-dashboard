# Fix: restore vacation modal save

## Summary

- Виправлено помилку, через яку після останніх оновлень календаря неможливо було зберігати періоди відпусток із HR-модалки.
- Збережено локальний snapshot співробітника для модалки та переведено запис у Firestore на атомарний batch, щоб уникнути збоїв під час повторних ререндерів.

## Changes

- `app.js` – зберігаємо копію обраного співробітника (`employeeSnapshot`) і використовуємо її у всіх методах модалки, якщо живі дані тимчасово недоступні.
- `app.js` – переписано `commitModalChanges()` на `db.batch()`, а також додано детальніший лог і повідомлення про помилки.
- `app.js` – оновлено допоміжні виклики, щоб розрахунок лімітів і селектори не падали при короткочасних оновленнях даних.

## Tests / Validation

1. HR View → відкрити співробітника, додати новий період → "Зберегти" → дані з’являються у Firestore та на UI без помилок.
2. Відредагувати існуючий період → "Зберегти" → зміни зберігаються, натомість попередні записи не дублюються.
3. Видалити період → "Зберегти" → запис зникає з Firestore і з таблиці одразу після оновлення.
4. Перевірено лог консольного повідомлення: у разі відмови відображається текст помилки з деталями.

## Root cause

- Під час ререндерів після оновлень календаря локальний масив `appData.employees` міг тимчасово не містити співробітника, для якого була відкрита модалка. `commitModalChanges()` отримував `undefined` та кидав помилку, що призводило до повідомлення "Не вдалося зберегти".
- Додатково транзакція містила зайві повторні спроби; перехід на batch знімає залежність від `runTransaction` і спрощує життєвий цикл запису.
